# phigd Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Owned by:** `plans/052-phig-server.md`. That plan holds the design and the
reasoning; this file is the execution script. If the two disagree, 052 wins and
this file is wrong.

**Goal:** Build `phigd`, a headless HTTP daemon over `phig-core`, serving a phig
collection to remote clients: paged queries, per-image metadata, duplicates,
people and faces, tag/gallery/favorite writes, three long-running operations
with polled progress, and media — thumbnail bytes, originals, byte-range video.

**Architecture:** A new top-level `server/` producing a static library
`phig-server` plus a thin `phigd` executable. The library exists so tests can
link it and drive a daemon in-process. `phig-server` links `phig-core`
directly, exactly as `cli/` does — it is a peer, not a client of `libphig`.
libmicrohttpd multiplexes connections onto a small thread pool; handlers never
block on those threads, instead suspending the connection, running phig work on
a separate worker pool, and resuming.

**Tech Stack:** C++20, CMake, libmicrohttpd 0.9.75+, nlohmann/json, libcurl
(tests only — already a phig dependency), GoogleTest.

## Global Constraints

- **C++20.** Match the surrounding style; `clang-format` with the repo's
  `.clang-format` (Google, 4-space, 100-col) must pass.
- **First-party code builds with `-Wall -Wextra`**; CI configures
  `-DPHIG_WERROR=ON`. Use the existing `${PHIG_WARNINGS}` variable, as
  `cli/CMakeLists.txt` does.
- **All logging goes through `core/log.h`** — `log_info` / `log_warn` /
  `log_error`. No spdlog includes anywhere in `server/`.
- **Every test fixture gets its temp directory from `tests/temp_dir.h`** via
  `make_temp_dir("label")`. A hardcoded temp path passes alone and fails under
  `ctest --parallel`.
- **No exception escapes a request handler.** Wrap every handler body in
  `try`/`catch (...)` and map to a 500 with a JSON error object. This mirrors
  the `PHIG_TRY` rule at the ABI boundary.
- **No client-supplied path is resolved against the filesystem**, except a scan
  target, which must canonicalize under `[server] scan_roots`.
- **New test files must be added to the `phig-tests` target** in the root
  `CMakeLists.txt` — the file list is explicit, not globbed.
- **libmicrohttpd version floor is 0.9.75** (Ubuntu 22.04). `enum MHD_Result`
  exists from 0.9.71, so use it rather than `int` returns.
- **Every commit message** ends with
  `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`.

## Milestones

Tasks 1–9 produce a working read-only server — enough for S3 (the web client)
to begin. Tasks 10–13 add writes, derived read surfaces and operations.

**Task 5 is a gate.** If MHD's suspend/resume does not behave as this plan
assumes under the epoll-plus-thread-pool mode, stop and reconsider the library
before writing tasks 6 onward. 052 records Drogon as the fallback.

### Task 2: JSON helper

A thin wrapper over nlohmann/json existing for one reason: phig indexes real
filenames, which may contain bytes that are not valid UTF-8, and nlohmann's
`dump()` **throws** on those by default. Every response built from a filename
would be a 500 waiting for the wrong photo.

**Files:**
- Create: `server/json.h`
- Modify: `CMakeLists.txt` (find nlohmann_json), `server/CMakeLists.txt`
- Test: `tests/test_server_json.cpp`

**Interfaces:**
- Produces: `namespace phigd { using Json = nlohmann::json; std::string
  dump(const Json&); Json parse_body(const std::string&, std::string& err); }`.
  `dump` never throws. `parse_body` returns a null Json and sets `err` on
  malformed input.

```cpp
#pragma once

#include <nlohmann/json.hpp>
#include <string>

namespace phigd {

using Json = nlohmann::json;

// Never throws. Filenames on disk are arbitrary bytes and nlohmann's default
// error handler throws on invalid UTF-8; `replace` substitutes U+FFFD instead,
// so one undecodable filename cannot turn a whole page into a 500.
inline std::string dump(const Json& j) {
    return j.dump(-1, ' ', false, Json::error_handler_t::replace);
}

// Returns a null Json and sets `err` on malformed input. Never throws.
inline Json parse_body(const std::string& body, std::string& err) {
    err.clear();
    Json j = Json::parse(body, nullptr, false);
    if (j.is_discarded()) {
        j = Json();
        err = "malformed JSON body";
    }
    return j;
}

}  // namespace phigd
```

### Task 3: Router

Pure path matching. No MHD, no phig — so route behaviour is testable without
starting anything.

**Files:**
- Create: `server/types.h`, `server/router.h`, `server/router.cpp`
- Test: `tests/test_server_router.cpp`

**Interfaces:**
- Produces:
  - `server/types.h`, holding `Request` and `Response` so the router can use
    the real handler type immediately. Task 4 consumes these unchanged rather
    than redefining them — an earlier draft had Task 3 store
    `std::function<void()>` and Task 4 swap the type out, which would have made
    Task 3's tests prove something Task 4 then replaced.

    ```cpp
    struct Request {
        std::string method, path, body;
        std::map<std::string, std::string> params, query, headers;
    };
    struct Response {
        int status = 200;
        std::string content_type = "application/json";
        std::string body;
        std::map<std::string, std::string> headers;
        int fd = -1;                              // >= 0 serves from a file
        uint64_t fd_offset = 0, fd_length = 0;
    };
    ```
  - `struct RouteMatch { bool matched = false; bool method_allowed = false;
    std::map<std::string, std::string> params; };`
  - `class Router` with `using Handler = std::function<Response(const Request&)>;`,
    `void add(const std::string& method, const std::string& pattern, Handler h);`
    and `RouteMatch match(const std::string& method, const std::string& path,
    Handler& out) const;`
  - Patterns use `{name}` for a single path segment: `/api/v1/images/{id}`.

```cpp
    MHD_OPTION_CONNECTION_LIMIT, static_cast<unsigned>(cfg_.connection_limit),

    MHD_OPTION_END);
```

`MHD_USE_EPOLL` is Linux-only; on macOS fall back to
`MHD_USE_INTERNAL_POLLING_THREAD | MHD_ALLOW_SUSPEND_RESUME` behind
`#ifdef __linux__`. Read the bound port back with
`MHD_get_daemon_info(daemon_, MHD_DAEMON_INFO_BIND_PORT)`.

`access_handler` is a static trampoline returning `enum MHD_Result`. It
accumulates the upload body across calls (MHD invokes the handler repeatedly
while `*upload_data_size` is non-zero), then on the final call builds a
`Request`, routes it, and queues the `Response`. Wrap the handler body in
`try`/`catch (...)` producing
`json_error(500, "internal", "unhandled exception")`.

For a buffer response use `MHD_create_response_from_buffer(body.size(),
body.data(), MHD_RESPMEM_MUST_COPY)`. `MUST_COPY` rather than `PERSISTENT`
because the body is a local `std::string`.

`register_routes(Server&, Database&, const ServerConfig&)` is declared in
`server/http.h` and defined in `resources_server.cpp`. It calls one registrar
per resource file — `register_server_routes`, and later
`register_image_routes`, `register_media_routes`, `register_write_routes`,
`register_dupes_routes`, `register_ops_routes`. Task 4 defines only the first;
each later task adds its own registrar and one call here, so no task has to

- [ ] **Step 3: Implement `WorkerPool`**

A fixed thread count, a bounded `std::deque<std::function<void()>>`, a mutex
and condition variable. `submit` returns false when `size() >= capacity`

- [ ] **Step 4: Implement the suspend/resume bridge**

Per-connection state stored in `*con_cls`:

```cpp
struct ConnState {
    std::string upload;               // accumulated request body
    bool submitted = false;
    std::atomic<bool> ready{false};
    Response response;
};
```

On the final handler invocation for a deferred route: if `!submitted`, set
`submitted = true`, `MHD_suspend_connection(connection)`, and `submit` a job
that runs the handler, stores into `state->response`, sets `ready`, then calls
`MHD_resume_connection(connection)`. Return `MHD_YES`. When MHD re-invokes the
handler and `ready` is set, queue the response.

Two things to get right:

- **Suspend before submit, or accept the race.** If the job finishes and calls
  `MHD_resume_connection` before `MHD_suspend_connection` has run, MHD resumes a
  connection that was never suspended. Call `MHD_suspend_connection` first, then
  submit.
- **`MHD_OPTION_NOTIFY_COMPLETED` frees `ConnState`.** A client that disconnects
  while suspended still triggers the completion callback, but only after the
  connection resumes — so the job must always resume, including on the error
  path. Put the resume in a scope guard, not at the end of the happy path.

If `submit` returns false, do not suspend: queue a 503 with `Retry-After: 1`
immediately.
