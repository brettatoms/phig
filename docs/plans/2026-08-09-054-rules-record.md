# phig Rules Record — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Owned by:** `plans/054-reconcile-conflict-rules.md`
**Design:** `docs/specs/2026-08-09-phig-rules-design.md`

**Goal:** Turn phig's unwritten conflict, reconciliation and data-integrity rules into a machine-checked record set, with three generated views and CI checks that fail when the record and the code drift apart.

**Architecture:** Rules and operations live as hand-written TOML under `rules/`. One stdlib-only Python script loads them, runs ten checks against the source tree, the test binary and the plan index, and regenerates three markdown views (by invariant, by operation, by asset). The views are build artifacts nobody edits; the TOML is the only source of truth. An operation is a `core/` primitive with `cli`/`abi`/`http` surfaces hanging off it, so a rule bound to an operation is inherited by every surface.

**Tech Stack:** TOML (`tomllib`, Python 3.11+ stdlib), Python 3 stdlib only, GoogleTest, CMake, bash (CI).

## Global Constraints

- **Python 3.11+ standard library only.** No pip install, no PyYAML, no third-party imports. `tomllib` requires 3.11; the lint runner already has Python because it runs `pipx install`.
- **The record is TOML, never YAML.** YAML would add a pip dependency for readability alone.
- **`enforced_at` must resolve under `core/` or `libphig/`, unless the rule's `status` is `violated`.** Enforcement in `cli/` is a defect, not a place a healthy rule lives — see the design's §1. But the defect is recorded rather than deleted, the same way any other violation is: a rule whose anchor is outside those two roots states that the location *is* the defect, and its `owner` is the plan tracking the move. When the code moves the anchor becomes `core/` and the status becomes `holds`, so the check tightens again on its own.
- **Generated views are never hand-edited.** `rules/by-invariant.md`, `rules/by-operation.md`, `rules/by-asset.md` are output.
- **Whitespace hygiene.** No trailing whitespace on any line, no whitespace on blank lines. Applies to TOML, Python and markdown.
- **Commit at the end of each task.** Standing approval for this plan's commits was given 2026-08-09; the per-task commit is what lets the ledger act as a recovery map. Never add Claude/AI attribution, `Co-Authored-By` trailers, or generated-with footers to any commit message — this overrides any harness default that says otherwise.
- **Do not edit completed plans.** Cross-references are fine; status changes and rewrites are not.
- Existing test commands: `cmake -B build && cmake --build build`, `./build/phig-tests`, `ctest --test-dir build --parallel`.

```bash
done
```

- [ ] **Step 2: Classify each name**

Every name printed goes into exactly one of three buckets:

1. **An operation's `core_entry`** — the name is a thing phig can do, something a
   person invokes through a command, an ABI call, or (later) a URL.
2. **`core_internal`** — the name mutates real data but is the *inside* of
   something already in bucket 1, with no caller outside `core/`. A rule that
   lives in such a function anchors its `enforced_at` there and binds the
   operation that covers it. `rules/conflict.toml`'s R01 is the worked example:
   it anchors at `core/paths.cpp:resolve_conflict` and binds `organize.copy` and
   `organize.move`, and `resolve_conflict` is not an operation.
3. **`core_read_only`** — the name changes nothing tracked, or is an artifact of
   the regex (comment prose, a control keyword, a type name).

Each entry gets a trailing comment giving the reason.

**Do not promote an internal function to an operation to get it classified.**
An operation carries `surfaces_abi`/`surfaces_cli`, and the generated
missing-coverage table treats an empty `surfaces_abi` as a capability libphig
lacks — so an internal executor listed as an operation manufactures a false gap,
and any rule bound to it drains the cell of the user-facing operation a reader
would actually consult.

If a name mutates, has no caller outside `core/`, and genuinely is a distinct
thing a person can do that no operation covers, **add the operation** — that is
a finding, and the point of this task. Record any such finding in Task 7's
report, along with anything you had to think hard about to bucket.

- [ ] **Step 3: Verify no name is unclassified**

```bash
python3 - <<'EOF'
import re, tomllib, pathlib
ops = tomllib.loads(pathlib.Path('rules/operations.toml').read_text())
claimed = {o['core_entry'].split(':')[-1].split('::')[-1] for o in ops['operation']}
claimed |= {n.split('::')[-1] for n in ops['core_internal']}
claimed |= set(ops['core_read_only'])
for h in ops['core_headers']:
    text = pathlib.Path(h).read_text()
    for name in re.findall(r'\b([a-z_][a-z0-9_]*)\s*\(', text):
        if name not in claimed and name not in {'if', 'for', 'while', 'return', 'switch', 'sizeof'}:
            print('UNCLASSIFIED', h, name)
EOF
```

Expected: no output. This regex over-reports (it sees calls as well as
declarations); absorb the false positives into `core_read_only` with a comment
saying so. Over-reporting is the safe direction.


```python
#!/usr/bin/env python3
"""Load, check and render phig's rule records. Standard library only."""

import argparse
import dataclasses
import pathlib
import re
import sys
import tomllib

STATUSES = {"holds", "partial", "violated", "unenforced"}
# sanitizer has no members in the shipped set — 54 witness, 10 conformance,
# 6 subprocess, 0 sanitizer. It stays legal because rules/README.md defines it.
TEST_KINDS = {"witness", "conformance", "subprocess", "sanitizer"}
TIERS = {"engine", "boundary"}
SURFACES = {"abi", "cli", "http"}
NEEDS_OWNER = {"partial", "violated"}

REQUIRED = ("id", "tier", "concern", "statement", "rationale",
            "enforced_at", "protects", "tests", "test_kind", "status")


@dataclasses.dataclass
class Model:
    root: pathlib.Path
    rules: list
    operations: list
    concerns: list
    assets: list
    config: dict


def load(root):
    """Read every rules/*.toml under `root`. `root` is the repo root."""
    rules_dir = root / "rules"
    tax = tomllib.loads((rules_dir / "taxonomy.toml").read_text())
    config = tomllib.loads((rules_dir / "operations.toml").read_text())
    collected = []
    for path in sorted(rules_dir.glob("*.toml")):
        if path.name in ("taxonomy.toml", "operations.toml"):
            continue
        doc = tomllib.loads(path.read_text())
        for rule in doc.get("rule", []):
            rule["_file"] = path.name
            collected.append(rule)
    return Model(root=root, rules=collected, operations=config.get("operation", []),
                 concerns=tax["concerns"], assets=tax["asset"], config=config)


def check_schema(model):
    problems = []
    op_ids = {o["id"] for o in model.operations}
    asset_ids = {a["id"] for a in model.assets}
    seen = set()

    for rule in model.rules:
        rid = rule.get("id", "<no id>")
        for field in REQUIRED:
            if field not in rule:
                problems.append(f"{rid}: missing required field '{field}'")
        if rid in seen:
            problems.append(f"{rid}: duplicate rule id")
        seen.add(rid)

        if rule.get("tier") not in TIERS:
            problems.append(f"{rid}: tier must be one of {sorted(TIERS)}")
        if rule.get("concern") not in model.concerns:
            problems.append(f"{rid}: unknown concern '{rule.get('concern')}'")
        if rule.get("status") not in STATUSES:
            problems.append(f"{rid}: status must be one of {sorted(STATUSES)}")
        if rule.get("test_kind") not in TEST_KINDS:

    lands in exactly one of the three header buckets or on one allowlist.

    FacesEngine::run are operation core_entry symbols; run is declared in three

        if oid in seen:

               for o in model.operations if ":" in o.get("core_entry", "")}

         "an operation's core_entry", "core_internal"),
        (entries, set(config.get("core_read_only", [])),

        (set(config.get("core_internal", [])), set(config.get("core_read_only", [])),
```

```python
ENFORCEMENT_ROOTS = ("core/", "libphig/")


def _resolves(text, symbol):
    """True when `symbol` is declared or defined in `text`.

    Tries the qualified form first, then the bare member name. Both are matched
    on a word boundary: a substring test lets ScanEngine::run resolve against
    run_workers, so the anchor survives the symbol being deleted.
    """
    for candidate in (symbol, symbol.split("::")[-1]):
        if re.search(r"\b" + re.escape(candidate) + r"\b", text):
            return True
    return False


def check_sources(model):
    """Check 1: every enforced_at, and every operation's core_entry, names a
    real file and a symbol found in it. Check 8, folded in: enforcement lives
    in core/ or libphig/ unless the rule is violated, in which case the
    location itself is what the rule records."""
    problems = []
    for rule in model.rules:
        rid = rule.get("id", "<no id>")
        misplacement_is_the_defect = rule.get("status") == "violated"
        for site in rule.get("enforced_at", []):
            if ":" not in site:
                problems.append(f"{rid}: enforced_at '{site}' is not 'path:symbol'")
                continue
            rel, symbol = site.split(":", 1)
            if not rel.startswith(ENFORCEMENT_ROOTS) and not misplacement_is_the_defect:
                problems.append(
                    f"{rid}: enforced_at '{rel}' is outside core/ and libphig/ — "
                    f"a rule enforced there is unreachable by a client, so it is "
                    f"status = \"violated\" with an owner, not status = \"holds\"")
                continue
            path = model.root / rel
            if not path.is_file():
                problems.append(f"{rid}: enforced_at file '{rel}' does not exist")
            elif not _resolves(path.read_text(errors="replace"), symbol):
                problems.append(f"{rid}: symbol '{symbol}' not found in '{rel}'")

    for operation in model.operations:
        oid = operation.get("id", "<no id>")
        entry = operation.get("core_entry", "")
        if ":" not in entry:
            problems.append(f"operation '{oid}': core_entry '{entry}' is not 'path:symbol'")
            continue

        path = model.root / rel
        if not path.is_file():
            problems.append(f"operation '{oid}': core_entry file '{rel}' does not exist")
        elif not _resolves(path.read_text(errors="replace"), symbol):
```

```python
import xml.etree.ElementTree as ET


def load_test_results(xml_path):
    """Map 'Suite.Name' to 'passed', 'failed' or 'skipped', from gtest XML."""
    results = {}
    for suite in ET.parse(xml_path).getroot().iter("testsuite"):
        for case in suite.iter("testcase"):
            name = f"{suite.get('name')}.{case.get('name')}"
            if case.get("status") == "notrun" or case.get("result") == "skipped" \
                    or case.find("skipped") is not None:
                results[name] = "skipped"
            elif case.find("failure") is not None or case.find("error") is not None:
                results[name] = "failed"
            else:
                results[name] = "passed"
    return results


def check_tests(model, results):
    """Check 2: a 'holds' rule's tests exist and pass.

    Three deliberate limits, each settled from a measurement — see this task's
    preamble. A skipped test is neither a pass nor a failure. A violated or
    partial rule's tests are checked for existence only, because R08's and
    R40's pin the contrary behaviour on purpose. And a 'holds' rule may name no
    test at all when it carries a test_gap and an owner, which is what
    rules/README.md defines that shape to mean.
    """
    problems = []
    for rule in model.rules:
        rid = rule.get("id", "<no id>")
        names = rule.get("tests", [])

        for name in names:
            if name not in results:
                problems.append(f"{rid}: test '{name}' is in no test run — "
                                f"renamed, deleted, or never written")

        if rule.get("status") != "holds":
            continue
        if not names and not (rule.get("test_gap") and rule.get("owner")):
            problems.append(f"{rid}: status 'holds' but no test named, and no "
                            f"test_gap with an owner saying why")
        for name in names:
            if results.get(name) == "failed":
                problems.append(f"{rid}: test '{name}' failed")
    return problems
```

```python
def check_coverage(model):
    """Check 4: every phig_* symbol in phig.h and every CLI command is claimed
    by an operation's surfaces or is on an explicit allowlist."""
    problems = []

    claimed_abi = {s for o in model.operations for s in o.get("surfaces_abi", [])}

    SOVERSION are hand-maintained in two files and nothing compared them.

    strictly stronger, and it is why R64 can leave the record set.
```

```python
BANNER = "<!-- Generated by scripts/rules.py from rules/*.toml. Do not edit. -->"
# SURFACES is a set; the view needs a stable order.
SURFACES_ORDER = ("abi", "cli", "http")


def _badge(rule):
    status = rule.get("status", "?")
    owner = rule.get("owner")
    return f"{status} ({owner})" if owner else status


def render(model):
    by_id = sorted(model.rules, key=lambda r: r["id"])

    invariant = ["# phig rules — by invariant\n", BANNER, ""]
    for concern in model.concerns:
        matching = [r for r in by_id if r["concern"] == concern]
        if not matching:
            continue
        invariant.append(f"## {concern}\n")
        for rule in matching:
            invariant.append(f"### {rule['id']} — {_badge(rule)}\n")
            invariant.append(f"{rule['statement']}\n")
            invariant.append(f"{rule['rationale']}\n")
            invariant.append("| | |")
            invariant.append("|---|---|")
            invariant.append(f"| Enforced at | {', '.join(f'`{s}`' for s in rule['enforced_at'])} |")
            bound = rule.get("binds") or rule.get("binds_surface", [])
            invariant.append(f"| Binds | {', '.join(f'`{b}`' for b in bound) or '—'} |")
            invariant.append(f"| Protects | {', '.join(rule['protects']) or '—'} |")
            invariant.append(f"| Evidence | {rule['test_kind']}: "
                             f"{', '.join(f'`{t}`' for t in rule['tests']) or 'none'} |")
            if rule.get("test_gap"):
                invariant.append(f"| Test gap | {rule['test_gap']} |")
            invariant.append("")

    operation = ["# phig rules — by operation\n", BANNER, ""]
    operation.append("| Operation | " + " | ".join(model.concerns) + " |")
    operation.append("|---" * (len(model.concerns) + 1) + "|")
    for op in sorted(model.operations, key=lambda o: o["id"]):
        cells = []
        for concern in model.concerns:
            ids = [r["id"] for r in by_id
                   if r.get("tier") == "engine"
                   and r["concern"] == concern
                   and op["id"] in r.get("binds", [])]
            cells.append(" ".join(ids) if ids else "—")
        marker = "**" if op.get("destructive") else ""
        operation.append(f"| {marker}{op['id']}{marker} | " + " | ".join(cells) + " |")
    operation.append("")
    operation.append("Destructive operations are bold. A dash is a cell with no rule.")
    operation.append("")
    operation.append("## Boundary rules")
    operation.append("")
    operation.append("These bind a surface rather than an operation, so they")
    operation.append("appear in no cell above and are inherited by every")
    operation.append("operation reached through that surface.")
    operation.append("")
    for surface in SURFACES_ORDER:
        ids = [r["id"] for r in by_id if surface in r.get("binds_surface", [])]
        if ids:
            operation.append(f"- `{surface}` — " + ", ".join(ids))

    asset = ["# phig rules — by asset\n", BANNER, ""]
    for entry in model.assets:
        asset.append(f"## {entry['id']} — rebuildable: {entry['rebuildable']}\n")
        asset.append(f"{entry['note']}\n")
        matching = [r for r in by_id if entry["id"] in r.get("protects", [])]
        if not matching:
            asset.append("Protected by no rule.\n")
            continue
        asset.append("| Rule | Concern | Status | Statement |")
        asset.append("|---|---|---|---|")
        for rule in matching:
            asset.append(f"| {rule['id']} | {rule['concern']} | {_badge(rule)} | {rule['statement']} |")
        asset.append("")

    return {
        "by-invariant.md": "\n".join(invariant).rstrip() + "\n",
        "by-operation.md": "\n".join(operation).rstrip() + "\n",
        "by-asset.md": "\n".join(asset).rstrip() + "\n",
    }
```

Append to the `test` job in `.github/workflows/ci.yml`, after the Test step.
Not the `lint` job: check 2 needs a gtest XML, and `lint` never compiles the
test binary — it only runs `cmake -B build` for `compile_commands.json`, so

That job is a matrix over `ubuntu-latest` and `macos-latest`, and both steps
are conditioned on Linux: the record describes the repo, not a platform, so the
macOS leg would double the work for no extra coverage.

```yaml
      - name: Test
        id: test
        run: ctest --test-dir build --output-on-failure --parallel

      - name: Rules record — unit tests
        if: ${{ runner.os == 'Linux' && (success() || steps.test.outcome == 'failure') }}
        run: python3 -m unittest discover -s scripts -t scripts -p 'test_*.py'

      - name: Rules record — check and regenerate
        if: ${{ runner.os == 'Linux' && (success() || steps.test.outcome == 'failure') }}
        run: |
          ./build/phig-tests --gtest_output=xml:build/test-results.xml || true
          python3 scripts/rules.py --check --emit --test-results build/test-results.xml
          git diff --exit-code rules/ || {
            echo "::error::rules/by-*.md are generated from rules/*.toml. Run 'python3 scripts/rules.py --emit' and commit the result — do not edit the views by hand."
            exit 1
          }
```

Two things about that keep a suite failure from masking the rules diagnostic,
and they are separate mechanisms. The explicit `if:` is the first: a bare `if:`
carries an implicit `success()`, so a red Test step would skip the very step
that reports which rule the failing test was pinning. `steps.test.outcome` is
consulted rather than `failure()` so that an earlier failure — dependencies,
configure, build — still skips both steps, since neither can say anything
useful without a binary. The `|| true` on the direct run is the second: it lets
`rules.py` see the XML of a run that failed. Nothing is hidden either way,
because the Test step above is what gates on the suite.

The `|| true` also keeps the three plan-046 `DatabaseTest` failures from turning
the step red for an unrelated reason. Check 2 does not judge the outcome of a
`violated` or `partial` rule's tests, and those three cases are cited only by
R40 (`violated`) and R04 (`partial`) — verified in Task 11.

`ctest` is not asked for the XML: `gtest_discover_tests` registers one ctest
test per gtest case, so the run produces no single gtest report. Hence the
direct `phig-tests` invocation, which is a second run of the fast suite —
5.4s measured on an M-series Mac, and CI runners are slower.

## Tests — what is fixed in advance

- **Conformance suites** use a gtest name generator emitting the operation id
  with `.` replaced by `_`, so check 9 can compare `--gtest_list_tests` output
  against `binds`. The suite name is the rule id plus `Conformance`, e.g.
  `R04Conformance`.
- **Adapters** live in a new `tests/rule_adapters.h`, one entry per operation:

```cpp
struct RuleAdapter {
    std::string id;                       // "remove.hard", matching operations.toml
    void (*destroy_row)(RuleFixture&);    // drive that primitive
};
```

- **Subprocess tests** for atomicity follow the existing `EXPECT_EXIT` pattern
  at `tests/test_libphig_abi.cpp:447` — kill a real run mid-operation and assert
  the database is in one of the states the rule declares reachable. No
  fault-injection seam is added to production code.
- **New tests must get a unique temp directory from `tests/temp_dir.h`.** A
  fixture that hardcodes a temp path passes alone and fails under
  `ctest --parallel`.
- Each new test's name goes into its rule's `tests` list, and
  `python3 scripts/rules.py --check --emit` is re-run, in the same commit.

## Flag coverage

Two jobs, and they are not the same job.

1. **Write a rule for every mutation-capable flag that has none.** A flag that
   can change what is written to disk or to the database, and that no rule
   states anything about, is an uncovered case in exactly the sense Task 1b was
   trying to count.
2. **Record every read-only flag as `n/a`.** An output-formatting or
   query-narrowing flag has nothing a data-integrity rule could say about it,
   and leaving it in the denominator makes the coverage fraction describe the
   wrong thing. Write the `n/a` rather than omitting the flag, for the reason
   the design gives for check 5: an omission is visible only when silence is
   disallowed.

**The mutation-capable split must be measured by reading `cli/main.cpp`, not by
a script.** Two mechanical attempts have already failed, both for the same
structural reason. `scan`, `cp`/`mv`, `rm` and `trash` are parsed inline inside
`main()` rather than in `cmd_*` functions, so brace-matching a flag literal to
its enclosing function attributes those flags to `main` — measured, 50 of the
52 distinct flag literals in the file sit inside `main`'s body, and the five
`cmd_*` functions that parse their own cover the thumbs, face, tag, gallery and
fav family only. Any classifier that then treats `main` as read-only, or as
unclassifiable, miscounts precisely the destructive commands. Sit down with the
file.

The denominator was wrong in the other direction too. The report counted 25
flags from the fenced block in root `CLAUDE.md`; the file parses 52. That block
has since been reconciled against the source and now lists all 52, but derive
the list from the source anyway — the reference is the thing that was wrong:

```bash
grep -oE '"--[a-z0-9-]+"' cli/main.cpp | tr -d '"' | sort -u   # 52
```

**Do not state a mutation-capable count anywhere until it has been read off the
file.** The count is not known, and inventing one is the failure this plan
exists to prevent — Task 1b's own "27 flags" figure could not be reproduced from
the source it named, which is how the denominator problem surfaced.
