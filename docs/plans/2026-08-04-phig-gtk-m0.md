# phig-gtk M0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One window showing a virtualized grid of thumbnails over a real 29,953-image phig collection, where clicking a cell opens the system image viewer.

**Architecture:** `phig-gtk` is its own git repo consuming installed `libphig` through `pkg-config`. Three components: `PhigGalleryModel` (a custom `GListModel` holding a page LRU, not the collection), `ThumbLoader` (an async, cancellable queue that resolves thumbnail paths and loads files into textures), and the GTK shell. The two components holding logic are headless-testable; widget rendering is not.

**Tech Stack:** C (GTK4 + libadwaita, raw C API — not gtkmm), CMake + pkg-config, GLib testing, devenv/Nix.

**Spec:** `~/devel/phig/docs/specs/2026-08-04-phig-gtk-m0-design.md`

## Global Constraints

- **`phig-gtk` may only use `<phig/phig.h>`.** Never include a `phig-core` header, never link `phig-core`, never reference a `cv::Mat`. The repo boundary exists to make this impossible rather than merely discouraged.
- **Non-GUI functionality belongs in libphig, not here.** phig-gtk implements presentation and interaction only: widgets, list-model paging, texture caching, cancellation, rendering, input. It must not implement image decoding, thumbnail generation, EXIF or orientation logic, hashing, SQL, date normalisation, or path/selection semantics — all of that already exists in phig-core and is phig's to expose. If a task needs a capability the ABI lacks, **stop and say so**: adding it to libphig is a phig-side task, and reimplementing it GUI-side would fork the behaviour away from the CLI and every future client.
- **Do not add orientation handling.** EXIF orientation is already applied when the thumbnail is generated (`cv::imread` does it by default and phig never passes `IMREAD_IGNORE_ORIENTATION`; verified by pixel comparison at RMSE 0.017 vs the auto-oriented source). Cached thumbnails are already rotated, so rotating again at display time would double-apply it.
- **GTK calls happen only on the main thread.** libphig queries and file loads run on worker threads and post results back with `g_idle_add`. Nothing else is concurrent.
- **`get_item` must never block.** A non-resident page returns a placeholder and schedules a fetch.
- **`phig_image` strings are owned by their `phig_image_list`** and are invalid after `phig_image_list_free`. Anything the model retains must be copied. This is the single most likely source of a use-after-free in this codebase.
- **Absent string values are `""`, never NULL.** `blur_score` is `-1` when not computed.
- **No modal dialogs.** Errors surface as an in-window error page (fatal init) or an `AdwToast` (everything else).
- **Comments describe the present**, not what the code used to do or which task introduced it.
- **Three tuning values must be measured, not reasoned:** resident pages either side of the viewport, `ThumbLoader` thread count, texture cache byte budget. Start at 2 / 4 / 256 MB and record what actually holds 60 fps (Task 7).
- **Every GTK/libadwaita function named in this plan exists — but check its argument list.** Symbol existence was verified against the Nix store libraries at planning time: `gdk_texture_new_from_filename`, `gtk_file_launcher_new`, `gtk_file_launcher_launch`, `gtk_grid_view_new`, `gtk_signal_list_item_factory_new` in gtk4 4.18.5 and 4.22.4; `adw_application_new`, `adw_application_window_new`, `adw_toolbar_view_new`, `adw_header_bar_new`, `adw_status_page_new`, `adw_toast_new` in libadwaita 1.7.2. Headers were not available, so **parameter lists and ordering are unverified.** Check each against `$(pkg-config --variable=includedir gtk4)` before relying on it, and report any correction.

- [ ] **Step 1: Add `phig.pc` to phig**

Create `~/devel/phig/phig/phig.pc.in`:

```

Name: phig
Description: phig image collection C ABI
Version: @PROJECT_VERSION@

```

**The prefix is derived from `${pcfiledir}`, not substituted from
`@CMAKE_INSTALL_PREFIX@`.** A configure-time substitution bakes the prefix that was set
when CMake ran, so `cmake --install --prefix X` then emits a `.pc` claiming a *different*
prefix — silently wrong `-I`/`-L` for any consumer. Verified: with the substituted form,
installing to `/tmp/pctest` produced a file saying `prefix=/home/brett/.local`.
`${pcfiledir}` is the directory containing the `.pc`, so with the file at
`<prefix>/lib/pkgconfig/phig.pc` the `../..` resolves correctly wherever it lands.
`@PROJECT_VERSION@` is correct to substitute.

### Task 2: `PhigGalleryModel`

**Files:**
- Create: `src/gallery-model.h`, `src/gallery-model.c`, `tests/test-gallery-model.c`
- Modify: `CMakeLists.txt`

**Interfaces:**
- Consumes: `phig_ctx*`, `phig_query*`, `phig_query_count`, `phig_query_page`, `phig_image_list_free` from `<phig/phig.h>`.
- Produces: `PhigGalleryModel` (a `GObject` implementing `GListModel`), `PhigImageRow` (a `GObject` holding one row's copied fields), and `phig_gallery_model_new(phig_ctx*, phig_query*)`. Task 4 binds cells against `PhigImageRow`.

**Critical ownership rule.** `phig_image`'s `const char*` fields point into the `phig_image_list` and are freed with it. `PhigImageRow` must **own copies** (`g_strdup`) of every string it exposes, and the `phig_image_list` must be freed as soon as the page's rows have been built. Retaining a `phig_image` pointer, or a string from one, is a use-after-free.

- [ ] **Step 1: Write the failing test**

`tests/test-gallery-model.c`. It needs a real database; take the path from `PHIG_TEST_DB` and skip when unset.

```c
#include <glib.h>
#include <phig/phig.h>
#include "gallery-model.h"

typedef struct {
    phig_ctx* ctx;
    phig_query* query;
    PhigGalleryModel* model;
    int64_t total;
} Fixture;

static void fixture_set_up(Fixture* f, gconstpointer unused) {
    (void)unused;
    const char* db = g_getenv("PHIG_TEST_DB");
    g_assert_nonnull(db);
    phig_config cfg = {0};
    cfg.db_path = db;
    cfg.mode = PHIG_READ_ONLY;
    g_assert_cmpint(phig_init(&cfg, &f->ctx), ==, PHIG_OK);
    g_assert_cmpint(phig_query_new(f->ctx, &f->query), ==, PHIG_OK);
    phig_query_set_sort(f->query, PHIG_SORT_DATE, TRUE);
    g_assert_cmpint(phig_query_count(f->ctx, f->query, &f->total), ==, PHIG_OK);
    f->model = phig_gallery_model_new(f->ctx, f->query);
}

static void fixture_tear_down(Fixture* f, gconstpointer unused) {
    (void)unused;
    g_clear_object(&f->model);
    phig_query_free(f->query);
    phig_shutdown(f->ctx);
}

static void test_n_items_matches_count(Fixture* f, gconstpointer unused) {
    (void)unused;
    g_assert_cmpuint(g_list_model_get_n_items(G_LIST_MODEL(f->model)), ==,
                     (guint)f->total);
}

static void test_out_of_range_returns_null(Fixture* f, gconstpointer unused) {
    (void)unused;
    g_assert_null(g_list_model_get_item(G_LIST_MODEL(f->model), (guint)f->total));
    g_assert_null(g_list_model_get_item(G_LIST_MODEL(f->model), (guint)f->total + 1000));
}

static void test_get_item_returns_a_row_without_blocking(Fixture* f, gconstpointer unused) {
    (void)unused;
    /* A cold model has no resident page, so this exercises the placeholder path.
     * Asserting non-NULL alone would pass against a fully synchronous get_item,
     * so also assert no page became resident: a blocking implementation could
     * not satisfy that. */
    g_assert_cmpuint(phig_gallery_model_resident_page_count(f->model), ==, 0);
    GObject* item = g_list_model_get_item(G_LIST_MODEL(f->model), 0);
    g_assert_nonnull(item);
    g_assert_true(PHIG_IS_IMAGE_ROW(item));
    g_assert_true(phig_image_row_is_placeholder(PHIG_IMAGE_ROW(item)));
    g_assert_cmpuint(phig_gallery_model_resident_page_count(f->model), ==, 0);
    g_object_unref(item);
}

static void test_row_strings_survive_page_eviction(Fixture* f, gconstpointer unused) {
    (void)unused;
    /* The ownership rule: a row must own copies, so it stays valid after its
     * page's phig_image_list is freed and after enough scrolling to evict it. */
    PhigImageRow* row =
        PHIG_IMAGE_ROW(g_list_model_get_item(G_LIST_MODEL(f->model), 0));
    g_assert_nonnull(row);
    g_object_unref(row);  /* the placeholder; the real row is fetched below */
    phig_gallery_model_fetch_page_sync(f->model, 0);           /* test-only helper */
    row = PHIG_IMAGE_ROW(g_list_model_get_item(G_LIST_MODEL(f->model), 0));
    char* sha_copy = g_strdup(phig_image_row_get_sha256(row));

    /* Walk far enough to evict page 0 under any sane resident-window size. */
    for (guint i = 0; i < (guint)f->total; i += 200)
        phig_gallery_model_fetch_page_sync(f->model, i / 200);

    g_assert_cmpstr(phig_image_row_get_sha256(row), ==, sha_copy);
    g_free(sha_copy);
    g_object_unref(row);
}

static void test_resident_pages_stay_bounded(Fixture* f, gconstpointer unused) {
    (void)unused;
    for (guint i = 0; i < (guint)f->total; i += 200)
        phig_gallery_model_fetch_page_sync(f->model, i / 200);
    g_assert_cmpuint(phig_gallery_model_resident_page_count(f->model), <=,
                     phig_gallery_model_get_max_resident_pages(f->model));
}

int main(int argc, char** argv) {
    g_test_init(&argc, &argv, NULL);
    if (!g_getenv("PHIG_TEST_DB")) {
        g_printerr("PHIG_TEST_DB unset; skipping\n");
        return 77; /* automake/ctest skip convention */
    }
#define T(name, fn) \
    g_test_add("/gallery-model/" name, Fixture, NULL, fixture_set_up, fn, fixture_tear_down)
    T("n-items-matches-count", test_n_items_matches_count);
    T("out-of-range-returns-null", test_out_of_range_returns_null);
    T("get-item-no-block", test_get_item_returns_a_row_without_blocking);
    T("row-strings-survive-eviction", test_row_strings_survive_page_eviction);
    T("resident-pages-bounded", test_resident_pages_stay_bounded);
#undef T
    return g_test_run();
}
```

Three test-only helpers are referenced deliberately: `phig_gallery_model_fetch_page_sync`, `phig_gallery_model_resident_page_count`, and `phig_gallery_model_get_max_resident_pages`. Declare them in the header with a comment saying they exist for tests — synchronous fetching keeps the tests deterministic without a `GMainLoop`, and the counters are the only way to assert eviction.

**A sixth test is required, and it is the one that matters most.** The five above all avoid a `GMainLoop`, so none of them exercises the *async* path — worker completes, main-thread callback installs the page, `items-changed` fires. That is where the emission arguments live, and a wrong emission leaves the grid permanently grey while every other test passes. Add a test that:

- connects a handler to `items-changed` recording `(position, removed, added)`,
- triggers a real async fetch via `get_item` on a cold page,
- runs a `GMainLoop` until the handler fires, with a `g_timeout_add` guard that quits the loop and fails rather than hanging,
- asserts the recorded values are `(page_index * 200, n_rows, n_rows)` — not merely that a signal arrived.

Verify it by reverting the emission to `(position, 0, 0)` and confirming the test fails.

- [ ] **Step 4: Implement it**

Page size 200. Start with 2 resident pages either side of the requested page (a value Task 7 measures). On `get_item(n)`:

1. Out of range → return NULL.
2. Page resident → return a ref to the cached `PhigImageRow`.
3. Otherwise → schedule an async fetch for that page and return a placeholder row.

The async fetch runs `phig_query_page` on a worker thread (`GTask` with `g_task_run_in_thread`), builds owned `PhigImageRow` objects, frees the `phig_image_list`, then on the main thread inserts the page and emits `items-changed` for that range.

**Four things this async path gets wrong if written naively. All four were shipped and caught in review the first time.**

1. **The emission must be `items_changed(position, n_rows, n_rows)`, not `(position, 0, 0)`.** `removed == 0 && added == 0` tells GTK nothing changed, so `GtkGridView` never re-queries and the grid stays permanently grey. An in-place swap of equal counts is valid here because the total never changes after construction.
2. **Placeholders must be unique per position AND stable per position.** Both halves are load-bearing and it took two wrong answers to find that out:

   - A **fresh** object on every `get_item(n)` call breaks stability. `GtkSelectionModel` compares by pointer, so clicks select nothing or the selection is lost on redraw.
   - A **single shared** placeholder for all positions breaks uniqueness — and this is the worse failure. GTK's list-item manager (`gtklistitemmanager.c`) keys recycled widgets by item pointer identity, so one object claiming N positions emits `Gtk-WARNING: Duplicate item detected in list. Picking one randomly.` and **the grid renders empty**. Measured: 223 warnings on this collection, and a user looking at the app saw nothing but blank cells. Documented unsupported pattern (glib#3030).

   The correct shape is **one placeholder object per position, cached** — same pointer every time position `n` is asked for, different pointers for different positions. Bound the cache alongside the page LRU so a 29,953-row scroll does not accumulate one per row; drop a range's placeholders when its real page lands.

   **No headless test catches this.** It appears only in a real `GtkGridView`. The unit suite was fully green while the app displayed nothing, so the check that matters is `grep -c "Duplicate item detected"` on a real run — it must be 0.
3. **The task's free function must release `data->fetched`.** The `phig_image_list` leaks whenever a result is discarded — model finalized mid-fetch, or shutdown with a queued task. Set the field to NULL after handing it to the page constructor, or the leak becomes a double free.
4. **`ctx` and `query` are not owned by the model, so a `GWeakRef` on the model does not protect them.** A worker that resolves the weak ref, gets preempted, and resumes after the caller called `phig_shutdown` uses freed memory. Either wait for outstanding fetches in `dispose`, or give the model ownership of `ctx`/`query`. A weak ref alone narrows the race without closing it.

`phig_gallery_model_fetch_page_sync` does the same work synchronously, for tests.

Eviction: when resident pages exceed the budget, drop the least-recently-used. Rows already handed out survive because they are refcounted and own their strings.

### Task 3: `ThumbLoader`

**Files:**
- Create: `src/thumb-loader.h`, `src/thumb-loader.c`, `tests/test-thumb-loader.c`
- Modify: `CMakeLists.txt`

**Interfaces:**
- Consumes: `phig_thumb_lookup(phig_ctx*, const char* sha256, char* out_path, size_t out_len, bool* exists)`.
- Produces: `ThumbLoader`, `thumb_loader_new(phig_ctx*, guint n_threads, gsize cache_bytes)`, `thumb_loader_request(...)`, and a `ThumbResult` enum. Task 4 calls `thumb_loader_request` from cell bind.

**Contract detail:** `phig_thumb_lookup` returns `PHIG_OK` with `*exists == false` for a cache miss, and `PHIG_ERR_INVALID_ARG` when `out_len` is too small. Size the buffer with `PATH_MAX` and treat a too-small buffer as a bug, not a runtime condition.

- [ ] **Step 1: Write the failing test**

`tests/test-thumb-loader.c`. Requires `PHIG_TEST_DB` and a sha256 known to have a cached thumbnail — find one by scanning the cache directory, or take it from `PHIG_TEST_SHA`.

Cover:

- **hit yields a texture** — a sha with a cached file produces `THUMB_OK` and a non-NULL `GdkTexture`.
- **miss yields `THUMB_MISS`** — an all-zeroes sha (64 chars, no such file) produces `THUMB_MISS` and no texture, and **never decodes**.
- **cancel before dispatch never calls back** — cancel a request immediately, run the loop briefly, assert the callback did not run.
- **cancel after dispatch discards the result** — cancel while in flight; assert either no callback or a callback with a cancelled status, and never a texture delivered into a freed context.
- **cache respects its byte budget** — request more distinct thumbnails than the budget holds; assert `thumb_loader_cache_bytes(loader)` stays `<=` the budget.

Because these are asynchronous, drive a `GMainLoop` and quit it from the callback with a timeout guard so a hang fails rather than hanging CI.

- [ ] **Step 2: Register and run to see it fail**

Mirror Task 2 Step 2's CMake block for `test-thumb-loader`. Expected: FAIL on the missing header.

- [ ] **Step 3: Write the header**

```c
typedef enum {
    THUMB_OK = 0,     /* texture is non-NULL */
    THUMB_MISS,       /* no cached thumbnail; M0 does not generate one */
    THUMB_FAILED      /* the file exists but could not be loaded */
} ThumbResult;

/* Runs on the main thread. `texture` is owned by the loader's cache; ref it to
 * keep it. Not called at all if the request was cancelled before dispatch. */
typedef void (*ThumbCallback)(ThumbResult, GdkTexture* texture, gpointer user_data);

/* Request a thumbnail texture for `sha256` (64-char hex).
 *
 * Asynchronous and cancellable. `max_dim` is the largest edge the caller can
 * use; M0's backend ignores it because the cache holds one size, but it is in
 * the signature so a later backend that generates at a requested size — in
 * process or in a phig-decode subprocess — needs no call-site change.
 *
 * On a cache miss this replies THUMB_MISS. M0 never decodes. */
void thumb_loader_request(ThumbLoader* self, const char* sha256, guint32 max_dim,
                          GCancellable* cancellable, ThumbCallback cb, gpointer user_data);
```

- [ ] **Step 4: Implement it**

A bounded work queue plus `n_threads` workers (start at 4; Task 7 measures). A worker calls `phig_thumb_lookup`; on `exists == true` it loads the file with `gdk_texture_new_from_filename` off the main thread, then posts the result via `g_idle_add`. On `exists == false` it posts `THUMB_MISS` without touching the filesystem further.

Cache: hash sha256 → `GdkTexture*`, with an LRU list and a running byte total. Charge each texture `width * height * 4` bytes. Evict from the LRU tail until the total fits. A texture still referenced by a cell survives eviction from the cache because it is refcounted.

Cancellation: check `g_cancellable_is_cancelled` before dispatch and again before posting the result.


2. Remove the eviction loop → the byte-budget test must fail.

Revert both, and report the actual results. If a mutation survives, the test is asserting shape rather than behaviour — strengthen it before committing.

- [ ] **Step 2: Build the model and loader on startup, in the documented order**

The window must map before any query completes:

1. Present the window with an empty `GtkGridView`.
2. On a worker thread: `phig_init`, then `phig_query_new` + `phig_query_set_sort(q, PHIG_SORT_DATE, TRUE)`.
3. `phig_query_count`.

- [ ] **Step 3: Wire the `GtkListItemFactory`**

`GtkSignalListItemFactory` with `setup`, `bind`, and `unbind`:

- **setup:** build the cell — a `GtkPicture` inside a fixed-size `GtkFrame` or `GtkBox`. Set `content-fit` so thumbnails do not distort.

### Task 7: Measure, then set the tuning values

The spec leaves three numbers to measurement. This task is where they get decided, and it is the task the whole milestone exists for.

- [ ] **Step 1: Measure startup**

Instrument the path from `g_application_run` to first-page-applied. Print it, run it 5 times against `~/.local/share/phig/phig.db`, and report all five numbers plus the median.

The spec's budget is **under 500 ms**. For reference, the ABI calls alone measured 0.4 ms (`phig_init`), 1.3 ms (`count`), and 0.85 ms warm / 19 ms cold (first page) — so anything close to 500 ms is GTK or texture work, not the database.

- [ ] **Step 2: Measure scroll**

Run with `GDK_DEBUG=frames` (or `GTK_DEBUG=interactive` and the inspector's frame graph) and scroll the full 29,953-row range end to end. Record dropped frames and the worst frame time.

Starting points: 2 resident pages either side, 4 loader threads, 256 MB texture cache. For each, try at least one value above and one below, and report the frame numbers:

- resident pages: 1, 2, 4
- loader threads: 2, 4, 8
- cache budget: 64 MB, 256 MB, 512 MB

Watch RSS as well as frame time — a cache budget that holds 60 fps while using 2 GB is not a good answer.

- [ ] **Step 4: Set the values and write down why**

Bake in the values that actually measured well, each with a comment giving the number that justified it (present tense, no history). If a starting point turned out fine, say so — the point is that the number in the code is one somebody watched.

A short table: startup median, worst frame time cold and warm, and the chosen values with their rationale. This is the evidence the spec's success criterion asks for.

- [ ] **Step 6: State plainly whether M0 met its criterion**

The criterion is: **window under 500 ms, 60 fps scrolling the full grid with no stalls.** If it did not, say so with the numbers and what looked responsible — that is a finding, not a failure of the task. Do not adjust the criterion to match the result.
